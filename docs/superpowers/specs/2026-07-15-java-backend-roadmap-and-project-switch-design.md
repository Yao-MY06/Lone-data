# Java 后端求职路线与项目切换设计

日期：2026-07-15  
状态：待用户复核  
目标：将当前主线切换为 Java 后端实习准备，以黑马点评生产级改造为核心项目，以 DeerFlow-Java 扩展平台为差异化项目，并在 2026 年 9 月开始投递。

## 1. 当前事实

- JavaSE 已学约七八成，具备 C++ 基础。
- JavaWeb、Spring Boot、苍穹外卖和黑马点评尚未开始。
- 嵌入式比赛未进入初赛，不再占用 P0，也不保留任务债。
- 图书借阅项目当前无法继续，暂停并退出 P0。
- 日常可用时间很多，但计划按约 6 小时有效投入设计，不按全天满负荷排程。
- 求职方向为 Java 后端实习，计划 9 月至 10 月边投递、边学习、边完善项目。

## 2. 核心决策

采用项目牵引、串行推进：

`JavaSE 收尾 -> JavaWeb/Spring Boot -> 苍穹外卖练手 -> 原版黑马点评 -> 生产级改造 -> 投递 -> DeerFlow-Java MVP`

同时只有一个 P0。算法和八股是限时辅助线，不构成第二项目。日期是目标窗口，阶段是否结束由可观察验收决定；若进度落后，先缩小练习范围，不跳过关键能力，也不无限顺延投递。

不采用以下路径：

- 先学完全部课程再做项目：反馈太晚，容易到 10 月仍无作品。
- 黑马点评与 Agent 同时开发：同时跨越 Java 基础、微服务和 Python Agent，失败风险过高。
- 一开始把黑马点评拆成五六个服务：会形成配置堆积，缺少业务理解和真实证据。

## 3. 时间线与阶段验收

### 3.1 JavaSE 收尾：7 月 15 日至 18 日

学习范围：集合与泛型、异常、IO、线程基础、反射与注解。以诊断和补缺为主，不重新完整刷课。

验收：

- 能独立选择并使用常见集合，解释基本差异。
- 能处理异常并完成文件读写小任务。
- 能创建线程或线程池，解释共享状态的基础风险。
- 能看懂反射和注解的基础用法。
- 完成一个综合小程序或自测，暴露的关键缺口已有修正。

### 3.2 JavaWeb 与 Spring Boot：7 月 19 日至 28 日

学习范围：HTTP、REST、Spring Boot 分层、参数校验、统一异常、MyBatis/MyBatis-Plus、MySQL、登录认证基础。SSM 只理解必要概念，不单独完整学习。

验收：

- 独立创建并启动 Spring Boot 项目。
- 完成一个包含登录、参数校验、统一异常和 MySQL CRUD 的小型 API。
- 能解释 Controller、Service、Mapper 的职责和一次请求的数据流。
- 接口经过实际调用验证，错误路径可复现。

### 3.3 苍穹外卖：7 月 29 日至 8 月 10 日

用途仅为练手与巩固，不作为简历核心项目。前端只需能配合后端联调，不投入时间学习界面实现。

验收：

- 核心后端流程由本人实际敲通，而非只观看视频。
- 能独立定位一次真实接口或数据库问题。
- 能说明认证、分层、数据库访问和业务状态流转。
- 非核心功能可删除，不追求完整复刻课程。

### 3.4 原版黑马点评：8 月 11 日至 31 日

先完成教学项目，理解原始实现，再做架构升级。核心范围包括登录、商户缓存、优惠券秒杀、Redis 锁或 Lua、消息处理、Feed、GEO 和签到等课程主线。

验收：

- 核心流程能够运行并通过真实操作验证。
- 能解释缓存穿透、击穿、雪崩，一人一单、分布式锁、Lua 原子性和异步下单。
- 能说明 Redis Stream 原实现的边界，而不是只会背结论。
- 形成基线架构图、已知问题和下一阶段改造依据。

### 3.5 黑马点评生产级改造：9 月 1 日至 15 日

只承诺三个方向：

1. **有限微服务拆分**：按业务域拆为 `user`、`shop/content`、`trade`，引入 Gateway、Nacos、OpenFeign、Sentinel。拆分必须说明边界、调用链和失败方式。
2. **秒杀链路深化**：Redis Lua 资格判断、MQ 异步下单、幂等、失败重试、最终一致性和对账。比较 Redis Stream 与选用 MQ 的真实取舍，不为使用中间件而替换。
3. **工程证据**：真实压测、慢查询与索引分析、链路追踪、关键指标、错误诊断和 Docker Compose。简历只写可复现数据。

验收：

- 至少一条完整秒杀链路可运行并覆盖主要失败路径。
- 服务拆分有实际调用，不是空壳模块。
- 有改造前后的真实基线、环境、方法和结果；无数据写未知。
- README 能解释三个改造的原因、代价和未解决问题。

### 3.6 投递与持续完善：9 月 15 日起

达到可演示的黑马点评版本后即开始投递，不等待所有候选技术完成。根据岗位反馈补八股、算法、JUC/JVM、MySQL/Redis 原理和项目证据。项目问题优先于新增课程。

### 3.7 DeerFlow-Java MVP：9 月下旬至 10 月

Python DeerFlow 仅负责 Agent 编排和 LLM 调用；Java 承载可验证的工具与状态服务。

MVP 组件：

- 一个 Java MCP Server，至少暴露两个受限工具，例如知识检索、受限数据查询或产物保存。
- 一个 Java Memory Service：Redis 保存短期会话状态，MySQL 保存长期记录。
- Docker Compose 启动 Java 服务及必要依赖。
- DeerFlow 到 Java 服务的真实调用链、超时、非法参数和工具失败可观察。

MVP 验收：

- DeerFlow 能真实调用至少两个 Java 工具。
- 会话信息能够写入并在后续调用中重新读取。
- 失败路径返回明确错误，不泄露密钥或敏感数据。
- README 解释跨语言边界：Python 负责编排，Java 负责工程服务。
- 不使用未经实测的性能或规模表述。

## 4. 日常时间结构

按约 6 小时有效投入设计：

| 时间 | 用途 |
|---|---|
| 09:00-11:30 | 当前阶段的新知识与最小练习 |
| 13:30-16:00 | 独立编码、项目实现和调试 |
| 19:30-20:15 | LeetCode：一道新题或一道复做题 |
| 20:30-21:00 | 验收当日结果，写明天第一步 |

其他时间是吃饭、运动、休息和意外缓冲，不再塞入固定学习任务。状态较差时只执行当前面板的最低完成线。

辅助线规则：

- LeetCode 每周 4 至 5 次，每次不超过 45 分钟。不会时可查思路，48 小时后脱离答案复做；不以背代码替代理解。
- 八股从黑马点评阶段开始，每次最多 30 分钟，并关联当天项目问题。
- MySQL、Redis、MQ 和 Spring Cloud 跟随项目学习，不完整刷完课程后才动手。
- JUC/JVM 在原版黑马点评完成后集中补充，优先解决项目和面试中实际暴露的问题。
- 主交付物未完成时，辅助线不得延长或挤占主线编码块。

## 5. 候选技术池

候选项必须保留，但默认不进入当前待办。只有当前承诺范围完成、候选项解决一个已验证问题，并且写清验收方式后，才可启用。

### 5.1 黑马点评候选项

- Caffeine + Redis 多级缓存。
- 布隆过滤器。
- Elasticsearch 复杂搜索与高亮。
- Canal + MQ 数据同步。
- XXL-Job 库存预热和异步对账。
- WebSocket/SSE 秒杀结果通知。
- Feed 推拉结合、智能排序和冷热分离。
- ShardingSphere 分库分表和读写分离。
- K8s 部署。
- 智能探店 Agent、多模态点评和 RAG。

启用示例：真实压测表明数据库读取是主要瓶颈后，才评估多级缓存；用户确有复杂搜索需求后，才评估 Elasticsearch；单库达到已测容量边界后，才评估分库分表。

### 5.2 DeerFlow-Java 候选项

- 更多 Java MCP Server：搜索、数据库、代码、文件处理。
- PGVector/Milvus 向量检索、记忆压缩和多租户隔离。
- XXL-Job/PowerJob 分布式任务调度和 DAG。
- Spring Cloud Gateway 工具调用网关。
- Sentinel 限流、熔断和缓存。
- Java + Docker 代码沙箱管理服务。
- RocketMQ 多 Agent 消息总线。
- Kafka 日志采集、WebSocket/SSE 进度推送。

以上都属于下一版本候选，不得在 MVP 尚未闭环时并行启动。
