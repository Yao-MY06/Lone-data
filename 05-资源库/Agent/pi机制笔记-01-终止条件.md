## Q2 为什么"批内全部工具结果都说停"才停，而不是一个说停就停？

- **我的原话（2026-10-21 16:05，猜测）**："可能会有多个工具没有成功返回结果，而且万一某个工具一直终止，可能会死循环"
- **我的原话（16:43，验证后）**："every、一批、不会（停），有个调用失败的"
- 位置（函数名 + 行号）：`types.ts` 的 `AgentToolResult.terminate` 注释；`agent-loop.ts` L690–692 `shouldTerminateToolBatch`
- **Q2 结论（本人答出，2026-10-21 16:43）**：

| 问 | 答 | 对不对 |
| --- | --- | --- |
| 判定用 `some` 还是 `every` | `every` | ✅ |
| `terminate` 的作用单位是"一次调用"还是"一批" | 一批（注释原文 *after the current tool batch*） | ✅ |
| 3 个工具里 1 个 `terminate=true`、另 2 个正常 → 会停吗 | 不会停 | ✅ 结论对 |
| 理由 | "有个调用失败的" | ⚠️ 半对 |

- **源码修正（AI 挑错）**：
  1. **理由要改**：不是"因为它失败了"，而是"**因为它没有把 `terminate` 置成 `true`**"。正常返回（`isError=false`）但没设这个字段的工具，一样让 `every()` 为假。字段默认是 `undefined` → 绝大多数工具根本不会设它。
     → **实际效果：除非一批里每个工具都明确喊停，否则永远不停。所以 `terminate` 本质是给"收尾型工具"用的（如汇总/提交），不是普通工具能随手触发的开关。**
  2. **猜测阶段答反的一处**：认为"工具一直终止会导致死循环"——方向反了。`terminate` 是刹车；死循环是**永远没人喊停 + 每轮还在产生新工具调用**。项目二 3.3 的循环防护防的是后者。
  3. **真正的原因（比"结果丢了"更硬）**：`terminate` 的语义是"**这一批跑完之后**停"。若任一即停，并行批次里会出现"assistant 消息声明 3 个 tool_call，transcript 里只有 1 个 tool_result" → **tool_call / tool_result 配对断裂**，下一次请求直接被 API 拒绝。所以终止必须在批边界生效，不能在中途生效。

## Q3 模型输出被 token 上限截断时，那批工具调用会怎样？为什么这样处理？

- **我的原话（2026-10-21 17:06）**："销毁，因为 json 参数很重要，所以可以看作原子性操作"
- 位置（函数名 + 行号）：`agent-loop.ts` L262–272（`stopReason === "length"` 分支）+ L478 `failToolCallsFromTruncatedMessage`
- **Q3 结论（本人答出，2026-10-21 17:06）**：
  - ✅ **对**：判断出"整批作废"，而不是"能跑几个跑几个"。
  - ⚠️ **"销毁"这个词要改**：不是把调用扔掉，而是**逐个判失败、并且仍然生成一条错误 tool_result**。理由和 Q2 同源 —— tool_call 与 tool_result 必须配对，扔掉就等于把 transcript 弄坏。
  - ⚠️ **"原子性"这个词用得偏**：这里没有回滚，只有"拒绝执行"。准确说法是 **"整批按不可信处理"**（全批不采信），不是事务原子性。
  - ⚠️ **理由没说到点上**：真正的理由是"输出被截断 → **参数 JSON 可能不完整或语义残缺** → 执行它会产生**假的成功结果**"。假成功比报错危险得多 —— 这和项目二 3.5 证据绑定是同一条原则：**输入不可信就不执行，宁可返回错误也不产生假证据。**

## 本轮三问总结（本人答出，AI 只挑错）

| 问 | 结论 | 首次作答准确度 |
| --- | --- | --- |
| Q1 有几种结束方式 | 3 个出口：模型失败/中断、外部决策、循环自然结束 | 第一轮只找到 2 个，改一次后补全 |
| Q2 为什么全批 terminate | `every()`；一批为单位；1 个喊停不停 | 结论全对，理由需从"失败"改为"没设 true" |
| Q3 截断怎么处理 | 整批不执行 | 结论对，两个用词需精确化 |

**可迁移到 Java 自研引擎的三条**：
1. 终止只在**批边界**生效，绝不在批中途 —— 否则 tool_call/tool_result 配对断裂。
2. `terminate` 是**收尾型工具的专用通道**，不是通用急停；普通工具默认不设它，所以"全批同意"实际等于"几乎永不自停"→ 必须有外部熔断（项目二 3.3）。
3. 输入不可信（截断/非法参数）时**整批判失败并留错误证据**，不挑着执行。
