**错在哪（结论层面，行号与机制留给你明晚讲）**
1. 最终总结不是工具调用。模型读完 pom.xml 后，直接用一条纯文本 assistant 消息回答，所以没有 edit / write。edit、write 是改文件用的，任务又明令不许改。
2. 一「轮」= 一次 assistant 回复 + 这批工具结果。这次第 1 轮调了 read，第 2 轮没有再调工具，就结束了。
3. stopReason 是每条 assistant 消息自己的字段，不是整个任务的成败：调工具的那条是 `toolUse`，正常答完是 `stop`。你选的 error / aborted 是失败出口才有的值。
4. 第 2 次请求时，历史里必须有「发出 read 调用的那条 assistant 消息」，工具结果才对得上它；role 要按源码原样写，不是「tools」。

**日志质量问题**：`run1.jsonl` 里有 13 行中文被控制台编码弄乱，JSON 已损坏（用户消息、最后一条 assistant 消息、`turn_end`、`agent_end` 等）。事件结构和计数仍可信（损坏行的 `type` 都能认出）。原因是 Windows PowerShell 5.1 按系统编码解码 node 的 UTF-8 输出，不是 pi 的问题，模型收到的任务和它的中文回答本身是正常的。重跑前先执行 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`，已写进基线笔记 §八。
