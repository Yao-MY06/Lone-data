## 0. 一句话总结

**登录这件事，Session 版靠"浏览器自动带 Cookie + 服务器自己存"；Redis 版把它拆开成"服务端发一个 token 存进共享的 Redis + 客户端每次手动带 token"。**

## 2. 块 B · Session 版登录（1.2–1.5）

### 2.1 三条链路

| 阶段 | 步骤 |
|---|---|
| ① 发送验证码 | 提交手机号 → 校验格式 → 生成 6 位码 → **存 Session（key = `code`）** → 发短信（开发态打日志） |
| ② 登录 / 注册 | 提交手机号 + 码 → 比对 Session 的码 → 按手机号查用户，**不存在则注册** → **存 Session（key = `user`）** |
| ③ 校验登录态 | 请求**自动带 Cookie(JSessionId)** → 拦截器取 Session → **存 ThreadLocal** → 放行 / 401 |

### 2.2 ThreadLocal 为什么存在

讲义先讲 tomcat 线程模型铺垫：监听线程接 socket → 从线程池取一个线程 → 走到 Controller/Service/DAO。**结论：每个请求独占一个线程。**

拦截器查出的用户怎么传给后面的 Service？一路当参数传太丑。**ThreadLocal = 线程隔离的全局变量**——同一请求内处处可 `getUser`，别的请求看不到。

`UserHolder` 是它的包装（`saveUser` / `getUser` / `removeUser`）。

> ⚠️ **必踩坑**：`removeUser()` 必须在 `afterCompletion` 里调。tomcat **复用线程**，不清理会让下一个请求读到上一个人的用户，**串号**。

### 2.3 拦截器注册

```java
registry.addInterceptor(new LoginInterceptor())
    .excludePathPatterns(              // 白名单
        "/shop/**", "/voucher/**", "/shop-type/**",
        "/upload/**", "/blog/hot",
        "/user/code", "/user/login")   // 登录接口不能拦
    .order(1);
```

### 2.4 隐藏敏感信息（1.5）

直接存 User 会把 `phone`、`password` 暴露给前端 → 改用 **UserDTO**（手机号通常脱敏为 `138****1234`）：

```java
session.setAttribute("user", BeanUtils.copyProperties(user, UserDTO.class));
```

## 3. 块 C · 为什么 Session 不行（1.6）

单机没问题，集群露馅：用户第一次请求落在 **tomcat1**（session 存 tomcat1），第二次落到 **tomcat2** → 没有 session → **401**。

**早期方案「session 拷贝」**（任一台改了 session 就同步给所有 tomcat）两个硬伤：

1. 每台都存**完整一份** session → 内存压力大
2. 同步**有延迟** → 中间仍可能被踢

**方案演进**：把 session 挪进 **Redis** —— 共享这件事就不用自己做了。

## 4. 块 D · 换成 Redis（1.7–1.9）

### 4.1 Session 版 vs Redis 版（关键差异）

| | Session 版 | Redis 版 |
|---|---|---|
| 验证码存哪 | Session，key 就叫 `code` | Redis `login:code:{phone}` |
| 用户信息存哪 | Session，key 就叫 `user` | Redis Hash `login:token:{token}` |
| 客户端带什么 | Cookie（JSessionId，浏览器自动） | 请求头 `authorization`（手动） |
| 谁能读到 | 只有存它的那台 tomcat | **所有 tomcat 共享** |

### 4.2 1.7 的三个设计决策

**① String 还是 Hash？** 讲义说"数据简单，两个都行"。项目选了 **Hash**：能只改一个字段，也能给整个 key 设过期，用户信息以后还可能加字段。

**② key 还能叫 `code` / `user` 吗？不能。** Session 是"每用户一份"，名字天然隔离；**Redis 是共享的**，都写 `code` 会互相覆盖 → key 必须带唯一标识。

**③ 用什么当唯一标识？不能用手机号。** 讲义要求 key ① 唯一 ② 方便携带——手机号都满足，**但敏感数据不宜在前端传递**。
→ **后台生成随机 `token`，前端每次请求带着它**：`String token = UUID.randomUUID().toString(true);`

### 4.3 1.8 登录的四个关键动作

```java
// 1. 从 Redis 取验证码比对（key 带手机号）
String cacheCode = stringRedisTemplate.opsForValue().get(LOGIN_CODE_KEY + phone);

// 2. 查用户，不存在则注册
User user = query().eq("phone", phone).one();
if (user == null) user = createUserWithPhone(phone);

// 3. UserDTO → Map，存进 Redis Hash
Map<String, Object> userMap = BeanUtil.beanToMap(userDTO, new HashMap<>(),
        CopyOptions.create()
            .setIgnoreNullValue(true)                          // ← 关键
            .setFieldValueEditor((f, v) -> v.toString()));      // ← 关键
stringRedisTemplate.opsForHash().putAll(LOGIN_USER_KEY + token, userMap);

// 4. 设过期 30 分钟
stringRedisTemplate.expire(LOGIN_USER_KEY + token, LOGIN_USER_TTL, TimeUnit.MINUTES);
```

**两行 `CopyOptions` 是学习日 2 的延续**：

- `setFieldValueEditor(v -> v.toString())` —— **所有字段值转字符串**，因为 `StringRedisTemplate` **只能存字符串**（对应学习日 2 的 `"21"`）。
- `setIgnoreNullValue(true)` —— 忽略 null，否则上面 `v.toString()` 遇 null 直接 **NPE**。

**两行缺一不可。**

### 4.4 1.9 双拦截器责任链

| | RefreshTokenInterceptor | LoginInterceptor |
|---|---|---|
| `order` | **0**（先） | **1**（后） |
| 拦什么 | `/**`（所有路径） | 只拦需登录路径 |
| 干什么 | 解析 token → 查 Redis → 存 ThreadLocal → **续期** | 只看 ThreadLocal 有没有用户 |
| 查不到用户 | **放行**（不拦） | — |
| 没有用户 | — | **401** |

**要解决的问题**：只在"需登录路径"上挂拦截器，用户浏览**免登录页面**（店铺/优惠券）时拦截器不执行 → **token 不续期** → 活跃用户也会 30 分钟后被踢。

**解法思想**：把「能认就认」和「该拦就拦」拆成两件事。第一个拦所有路径 → 免登录请求也经过它 → 续期生效；第二个逻辑简单到 4 行。

**细节**：`UserHolder.removeUser()` 清理放在 **RefreshTokenInterceptor 的 `afterCompletion`**（它拦 `/**`，才覆盖所有请求）。

## 5. 走读挖出的坑（讲义没强调）

| # | 坑 | 说明 |
|---|---|---|
| 1 | **`BeanUtils.copyProperties` 有两套 API** | 讲义 1.5 写的 `BeanUtils.copyProperties(user, UserDTO.class)` 是 **hutool** 的 `BeanUtil.copyProperties(source, Class)`；Spring 的是 `(source, target)`（传**目标对象**）。**只差一个 `s`**。苍穹学习日 4 踩的 null→int 坑是 **Spring 版**。 |
| 2 | **`CopyOptions` 两行缺一不可** | 见 4.3。`setFieldValueEditor` 防类型报错，`setIgnoreNullValue` 防 NPE。 |
| 3 | **讲义 1.8 代码有残留** | `login()` 签名还留着 `HttpSession session` 参数，且 `stringRedisTemplate` 未声明成字段 → **直接跑编译不过**，需删参数 + 注入。 |
| 4 | **讲义拼接痕迹** | 1.4 节（"Session 版"）贴的 `MvcConfig` 里已经出现 `RefreshTokenInterceptor` + `StringRedisTemplate`，那是 **1.9 的最终形态**。看讲义别被绕进去。 |
