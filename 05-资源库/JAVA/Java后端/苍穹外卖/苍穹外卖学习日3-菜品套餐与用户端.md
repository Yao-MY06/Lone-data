## 2. 公共字段自动填充（AOP）

### 2.1 三件套

| 文件 | 位置 | 职责 |
|---|---|---|
| `AutoFill.java` | `sky-server/annotation/` | 自定义注解，`value()` 携带 INSERT/UPDATE |
| `AutoFillAspect.java` | `sky-server/aspect/` | 切面，反射赋值 |
| `AutoFillConstant.java` | `sky-common/constant/` | 方法名字符串常量（**初始工程已有**） |

### 2.2 切点表达式逐段拆

```java
@Pointcut("execution(* com.sky.mapper.*.*(..)) && @annotation(com.sky.annotation.AutoFill)")
```

- `execution(* com.sky.mapper.*.*(..))` —— mapper 包下所有类、所有方法
- `&& @annotation(...)` —— **并且**方法上带了 `@AutoFill`

**AOP 的精髓在这个 `&&`**：把"拦截整个 mapper 包"收窄成"只拦我标了的"。没标注解的方法，切面根本不碰。

### 2.3 为什么用反射

```java
Object entity = args[0];  // 类型是 Object，可能是 Category/Dish/Setmeal
Method setCreateTime = entity.getClass().getDeclaredMethod("setCreateTime", LocalDateTime.class);
setCreateTime.invoke(entity, now);
```

切面里不知道 entity 具体是什么类，编译器无法调 `entity.setCreateTime()`。**反射是运行期按字符串找方法** → 一个切面通吃所有实体类。

INSERT 填 4 个字段，UPDATE 只填 `update_time/update_user`。

### 2.4 改造点

- `CategoryMapper.insert/update` 贴上 `@AutoFill`
- `CategoryServiceImpl.save/update/startOrStop` **删掉**手写的 4/2 行赋值

| 证据 | 内容 |
|---|---|
| 切面日志 | `com.sky.aspect.AutoFillAspect : 开始进行公共字段自动填充...` |
| 数据库 | 请求体只传 `{"name","sort","type"}`，DB 里 `create_time=2026-10-08 16:26:55, create_user=1` **全自动填好** |

| `SetmealMapper` 补齐 | DishServiceImpl 用到 `setmealMapper.update` |

### 3.2 关键机制

**① 主键回填 + 事务**
```xml
<insert id="insert" useGeneratedKeys="true" keyProperty="id">
```
插入菜品后，`dish.getId()` 拿到自增主键，再用来插口味表。`@Transactional` 保证两张表同成同败。

**② 一对多：先删后插**
```java
// 修改菜品口味
dishFlavorMapper.deleteByDishId(dishDTO.getId());  // 先删光
... insertBatch(flavors);                           // 再插新的
```
> **为什么不逐条 update？** 因为口味可能增删（3 个变 1 个），逐条改要处理增/删/改三种情况，代码爆炸。**"全删重插"最简单可靠**，口味数据量小，代价可接受。套餐关联表同理。

**③ 分页连表**
```xml
select d.*, c.name as categoryName from dish d
left outer join category c on d.category_id = c.id
```
把分类名带进 `DishVO`。

## 4. 套餐管理（8 接口）

### 4.1 与菜品的异同

**同**：都是"主表 + 关联表"，都用"先删后插"、都靠 `useGeneratedKeys` 回填主键。

**异**：
- 套餐的关联是 **setmeal_dish**（套餐-菜品）
- 分页/单查用 **`<resultMap>` + `<collection>` 做一对多嵌套映射**
- 起售时要**跨表校验套餐内菜品状态**

### 4.2 最有价值的：一对多嵌套映射

```xml
<resultMap id="setmealAndDishMap" type="com.sky.vo.SetmealVO" autoMapping="true">
    <result column="id" property="id"/>
    <collection property="setmealDishes" ofType="SetmealDish">
        <result column="sd_id" property="id"/>
        <result column="sd_name" property="name"/>
        ...
    </collection>
</resultMap>
```
SQL 用 `a.*, b.id sd_id, b.name sd_name` —— **给关联表的同名列起别名**（`sd_` 前缀），映射里按别名区分，避免和主表列冲突。

### 4.3 跨表业务校验（起售套餐）

```java
if (status == StatusConstant.ENABLE) {
    List<Dish> dishList = dishMapper.getBySetmealId(id);  // 反查套餐内的菜
    dishList.forEach(dish -> {
        if (dish.getStatus() == StatusConstant.DISABLE) {
            throw new SetmealEnableFailedException("套餐内包含未启售菜品，无法启售");
        }
    });
}
```

## 5. 购物车 + 地址簿（用户端，10 接口）

### 5.1 关键区别：用户端拦截器

- 管理端：`/admin/**`，header = `token`，secret = `itcast`
- 用户端：`/user/**`，header = **`authentication`**，secret = **`itheima`**

**必须补的配置**（`application.yml` 原本缺 user 的 jwt）：
```yaml
sky:
  jwt:
    user-secret-key: itheima
    user-ttl: 7200000
    user-token-name: authentication
```

### 5.2 微信登录没法真跑 → 降级方案

微信登录要真实 appid/secret 调微信接口，**跑不通**。但我们发现：**拦截器只校验 JWT 合法性**，所以可以**自己用 JwtUtil 造一个 user token**（userId=1）绕过微信，专注验证购物车/地址簿业务。

> **踩坑**：手写 token 时 `.signWith(HS256, "itheima")` **传 String 会失败**！项目里是
> `.signWith(signatureAlgorithm, secretKey.getBytes(StandardCharsets.UTF_8))` —— **必须传 byte[]**，
> 否则签名不匹配 → 401。且要 `.setExpiration()` 设过期时间。

### 5.3 购物车设计要点

| 机制 | 说明 |
|---|---|
| **同商品累加** | 先按 userId+dishId+flavor 查，有则 `number+1`，无则新插 |
| **服务端补全商品信息** | 只传 dishId，服务端反查 dish 表填 name/image/price |
| **减份非删除** | `number==1` 才删记录，否则只 `number-1` |

### 5.4 地址簿设计要点：设默认是事务

```java
@Transactional
public void setDefault(AddressBook addressBook) {
    // 1、当前用户所有地址 → 非默认
    addressBookMapper.updateIsDefaultByUserId(addressBook.setIsDefault(0));
    // 2、目标地址 → 默认
    addressBookMapper.update(addressBook.setIsDefault(1));
}
```
**必须先全置 0 再置 1**，否则会出现两个默认地址。两步必须在一个事务里。

## 6. 本日三大坑（重要！）

### 坑 1：命令行 mvn 走 JDK 25 → Lombok 全失效 ★★★

- **现象**：`找不到符号 log`、`找不到符号 getPrivateKeyFilePath()`，全项目报错
- **真因**：命令行 `mvn` 用系统 JDK 25，而 **Lombok 1.18.20 不支持 JDK 25**，注解处理器静默失效 → `@Data`/`@Slf4j` 不生成代码
- **解法**：`export JAVA_HOME="F:\path"` 再跑 mvn
- **教训**：**命令行构建和 IDE 构建的 JDK 可能不同**，报"找不到符号"先查 `mvn -v`
- **注意**：VSCode 里已配 JDK 11，所以 VSCode 编译是好的

### 坑 2：`mvn clean` 删不掉 target ★★

- **现象**：`Failed to delete ...\target`
- **真因**：VSCode 的 Java 语言服务器（JDT LS，`java.exe` 进程）锁着 `target/classes`
- **解法**：**别 clean**，直接 `mvn install`（增量编译够用）；或关 VSCode 再 clean
- Windows 特有文件锁问题，Linux/macOS 不会遇到

### 坑 3：`SERVER__PORT=53824` 环境变量污染（仅我的环境）★

- **现象**：`Port 53824 is already in use`
- **真因**：我的运行环境有 `SERVER__PORT=53824`，Spring Boot 会把 `SERVER__PORT` 映射成 `server.port`，覆盖 yml 的 8080
- **解法**：`env -u SERVER__PORT -u SERVER_PORT java -jar ...`
- **用户自己跑不会有此问题**

### 坑 4：后台进程被回收

- **现象**：启动应用后，下一条命令连不上
- **解法**：**启动+等待+测试+关闭写在同一个 bash 命令里**（已在本次全程使用）
