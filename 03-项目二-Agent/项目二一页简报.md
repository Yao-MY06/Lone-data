# 项目二一页简报（智能故障诊断与自动评测平台）

> 草案 v1（2026-10-21，Agent 会话起草）。**【待确认】项需用户拍板后才算立项门通过**；本页只满足 [[智能故障诊断与自动评测平台实施与验收]] §6.1 启动门第 2 项，模板来自 [[项目SOP]] §一。
> 完整目标与硬约束以 [[智能故障诊断与自动评测平台实施与验收]] 为准；战略定位见 [[大厂实习级双项目规划]]。

- **类型**：作品 / 研究（简历向）
- **用户/问题**：微服务系统出故障时，人工排查要在指标、日志、链路多个系统间来回翻，慢且依赖个人经验。输入一条告警，Agent 自己调受限工具逐步排查，输出**带证据链**的根因、置信度与修复建议；诊断质量用故障注入的 ground truth 自动判分，不靠感觉。
- **可见交付物（最小承诺范围）**：
  1. Java 诊断任务接口：至少一轮"选择工具 → 执行 → 回传 → 结论"，结构化报告含根因/证据引用/置信度/未完成检查；
  2. 两个受限诊断工具 + 三个故障场景 + 证据目录（冻结清单见下）；
  3. 可靠性机制最小切片：预算/轮次上限、重复调用分级处置、stall 检测、压缩熔断、**声明-证据绑定**（按 5a 引用存在性 → 5b 声明内容校验 → 5c 语义校验三档递进，首版只承诺 5a。**2026-10-24 更正：不再称「最强原创点」**，理由见 [[参考仓库调研-项目二#六、补充调研：故障诊断 + 知识检索（RAG）同类项目（2026-10-24）\|调研 §六]]）；
  4. 评测闭环一条：注入 → 采集 → 诊断 → 证据校验 → ground truth 比对 → 报告，正常与失败路径各可重复一次；
  5. 研究侧：《Claude Code 可靠性机制逆向分析》报告（2.2，源码基准 `chinasiro/claude-code-sourcemap` v2.1.88）。
- **截止窗口（2026-10-21 定，依据 [[AI协作上下文\|AI 协作上下文]]「项目二研究线时间配额」；2026-10-24 用户确认「按此」，本项不再待确认）**：
  - 配额：2.1 + 2.2 每周 **3 个晚间块**（周二、周四、周六 19:10–21:40，约 7.5 h）；项目一未达最低完成线时，当周让给项目一、不补。
  - 2.1 pi 认知基线：2026-10-20 起时间盒 → **2026-10-29 收口**（原 10-27 已超期，2026-10-28 重定；pi 已于 10-26 跑通，只剩 B1–B5 脱稿讲）。
  - 2.2 逆向报告：**初稿 2026-12-10**；2026-12-31 倒排检查不通过则先暂停项目二。
  - 工程闭环：6.1 启动门满足（项目一可观测数据源就绪）后启动，不早于项目一 P2。
- **15 分钟内第一步**：用户自己跑一次 pi 实派任务，补 2.1 产出物一的最后缺口——命令与观察点已备好，见 [[pi最小Agent认知基线]] §八（实测 CLI 1.3.0、`--list-models` 已确认 deepseek-flash / deepseek-v4-pro 在内）。
- **本轮验收标准**：以 [[智能故障诊断与自动评测平台实施与验收]] §6.3 最终阶段门为准（正常+受控失败路径可运行、两个受限工具四种证据、一个故障场景 ground truth + 程序化证据校验、一个可靠性机制消融对照、全链路可追溯、README 写明边界与失败语义）。
