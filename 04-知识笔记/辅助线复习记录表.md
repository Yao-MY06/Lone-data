> [!note]- 答案要点（对答案时才展开，先闭卷写完再看）
> 1. **ThreadLocal**：Entry 的 key 是弱引用（ThreadLocal 对象可被回收），value 是强引用，`ThreadLocal` 被回收后 key 变 null 但 value 仍被 Entry → value 那条链挂在线程上，线程常驻（尤其线程池）就不释放。弱引用只保证 key 能回收，不保证 value；所以必须 `remove()`。`get/set/remove` 会顺带探测式清理过期 key，但清不干净。
> 2. **HashMap**：容量 2 的幂 → `hash & (n-1)` 等价取模且位运算更快；扩容 2 倍使元素要么留在原位、要么移动 oldCap，无需重新计算 hash（`hash & oldCap` 判断高低位）。
> 3. **线程池**：core 满 → 进队列；队列满 → 扩到 max；max 也满 → 拒绝策略（Abort/CallerRuns/Discard/DiscardOldest）。`newFixedThreadPool` 用无界 `LinkedBlockingQueue`，队列永不溢出 → `maximumPoolSize` 形同虚设，任务堆积导致 OOM。
> 4. **synchronized vs ReentrantLock**：① 前者 JVM 关键字/后者 JDK API；② 前者自动释放、后者必须 `finally unlock()`；③ 后者支持公平锁、可中断、多条件变量（`Condition`）、`tryLock` 超时。锁升级：无锁 → 偏向锁 → 轻量级锁（CAS 自旋）→ 重量级锁（OS 管程）。
> 5. **thenApply / thenCompose**：前者 `Function<T,R>` 做变换，返回普通值；后者 `Function<T,CompletionStage<R>>` 做扁平化，避免嵌套 `CF<CF<R>>`。不指定 executor 时用**上一个任务的执行线程**（`thenApplyAsync` 才进 ForkJoinPool.commonPool 或指定池）。
> 6. **索引**：聚簇索引叶子存整行，按主键组织；二级索引叶子存主键值。查非索引列要拿主键回表；**覆盖索引**（查询列全在索引里）或走主键查询时不用回表。
> 7. **失效**：函数/运算作用在索引列上（`DATE(create_time)`）、隐式类型转换（字符串列传数字）、`%` 前缀模糊、`OR` 连接非索引列、联合索引不满足最左前缀、`!=`/`NOT IN` 大范围。项目里最容易踩：`order by` 与 `where` 索引顺序不一致导致 `filesort`。
> 8. **三大日志**：`redo log`（InnoDB 物理页修改，崩溃恢复，WAL 保证持久性）、`undo log`（逻辑反向操作，回滚 + MVCC 快照读）、`binlog`（Server 层逻辑日志，主从复制与归档）。顺序：先写 undo → 改内存页 → 写 redo（prepare）→ 写 binlog → redo commit。
> 9. **MVCC**：靠隐藏列（`trx_id`、`roll_pointer`）+ undo 版本链 + `ReadView`。`ReadView` 关键字段：`m_ids`（活跃事务 id 列表）、`min_trx_id`、`max_trx_id`、`creator_trx_id`。RC 每条 SELECT 都新建 ReadView，RR 只在第一次 SELECT 建、整个事务复用 → 这就是"可重复读"的来源。
> 10. **EXPLAIN**：看 `type`、`key`、`rows`、`Extra`、`filtered`。`type` 至少 `range`，`ref`/`eq_ref` 更好，`ALL` 是全校扫。`Using filesort` = 无法用索引顺序满足排序，额外排序开销；`Using temporary` = 用了临时表。
> 11. **三大缓存问题**：穿透=查不存在的 key → 空值缓存 / 布隆过滤器 / 参数校验；击穿=热点 key 过期瞬间打穿 → 互斥锁重建 / 逻辑过期；雪崩=大量 key 同时过期或 Redis 挂 → 过期时间加随机、多级缓存、熔断降级。项目里落地的是**互斥锁 + 逻辑过期**（笔记有、未落地，如实记账）。
> 12. **类型场景**：String（token、验证码、计数器）、Hash（用户对象、购物车）、List（简单队列/消息）、Set（点赞去重、共同关注 `SINTER`）、ZSet（Feed 收件箱、排行榜）；特殊：Bitmap（签到）、HyperLogLog（UV 去重）、GEO（附近商户）。黑马点评对应：`login:token:*`、`feed:{userId}`、`shop:geo:*`。
> 13. **持久化**：RDB 是内存快照（体积小、恢复快、可能丢最后一次快照后的数据）；AOF 是命令追加（更安全、文件大、恢复慢）。AOF 重写把冗余命令压缩成最小集合（如多次 `INCR` 合成一次 `SET`）。混合持久化 = 重写时 AOF 头部放 RDB 全量快照 + 尾部追加增量命令（Redis 4.0+）。
> 14. **单线程快**：纯内存 + epoll 多路复用 + 单线程免锁免上下文切换 + 高效数据结构。6.0 多线程指的是**网络 I/O 读写与协议解析**多线程，命令执行仍是单线程（不存在并发写数据结构的锁问题）。
> 15. **分布式锁五条件**：① `SET key value NX EX` 一条命令原子加锁（不能 `SETNX` + `EXPIRE` 两步）；② value 存唯一标识（UUID/线程 id）；③ 解锁必须比对 value 再删，且比对+删除要原子（Lua）；④ 过期时间要覆盖业务耗时（否则要续期/看门狗）；⑤ 失败要能快速失败或有限重试，不能无限自旋阻塞。
