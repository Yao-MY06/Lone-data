# Redis 五种数据类型与原子能力

> 定位：一张可随时翻的卡片。忘了"该用哪种类型"时看它。完整展开见 [[../05-资源库/JAVA/Java后端/黑马点评/黑马点评学习日1-Redis基础与环境|黑马点评学习日1]]。

## 一句话理解

**Redis 是一个跑在内存里的键值数据库；它的价值在于"过期 + 原子命令"，而这些原子命令是绑在五种数据类型上的——所以"选类型"其实是在选"哪些操作能一条命令做完、中途不被打断"。**

## 五种模具

| 类型 | 存什么 | 独家能力（别的类型做不到） | 后面用在哪 |
|---|---|---|---|
| **String** | 一个值 | **数字原子自增**（`INCR`） | 验证码、登录 token、缓存商户 JSON |
| **Hash** | 对象的多个字段 | **只改某个字段**，不用整体读改写 | 登录用户信息 |
| **List** | 有序、可重复 | **两头进出** | 消息队列雏形（学习日 6） |
| **Set** | 无序、去重 | **交 / 差 / 并**（`SINTER`/`SDIFF`/`SUNION`） | 点赞去重、共同关注（学习日 7） |
| **ZSet** | 带分数的 Set | **按分数排序** | 点赞排行榜、Feed 收件箱（学习日 7） |

> 后面还会遇到三个不像类型的名字——**GEO**（附近商铺）、**BitMap**（签到）、**HyperLogLog**（UV 统计）。它们的底子仍是上面几副模具：GEO 建在 ZSet 上，BitMap 建在 String 上，HLL 是一种特殊 String。

## 一个例子

它替 MySQL 挡掉了哪些"贵操作"：

| 需求 | MySQL 做法 | Redis 做法 |
|---|---|---|
| 验证码 5 分钟失效 | 定时任务扫表删过期行 | `SET sms:code:138... 123456 EX 300` |
| 并发计数 | 行锁 / 乐观锁 | `INCR`（单命令原子） |
| 共同好友 | 多表 JOIN | `SINTER` |
| 排行榜 | `ORDER BY score DESC` + 索引 | `ZREVRANGE` |

## 一个易错点

**Redis 里没有"数字类型"，字符串能不能当数字用是"按值的内容"动态判断的。**

```redis
SET n 10            → OK
INCRBYFLOAT n 0.5   → "10.5"
INCR n              → (error) ERR value is not an integer or out of range
```

`INCR` 系列会尝试把字符串解析成整数：`"10"` 行，`"10.5"` 不行。同一个 key 上一秒是整数、下一秒是浮点，这是它和 Java 强类型最不一样的地方。

## 另外三个必背的点

1. **`TTL` 三种返回值**：正数 = 还剩几秒；`-1` = 键存在但**永不过期**；`-2` = **键不存在**。
2. **`SETNX`** = SET if Not eXists，已存在时返回 `0` **且不改原值**（分布式锁的基石，学习日 5）。
3. **`ZRANK` 从 0 开始**数，且 `ZRANGE` 默认**分数从低到高**——做排行榜要用 `ZREVRANGE`。
