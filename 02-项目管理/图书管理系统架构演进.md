## 二、微服务拆分（4个核心服务）

| 服务 | 职责 | 核心表 |
|------|------|--------|
| `library-user-service` | 用户注册、登录、权限、JWT | user, user_role |

## 三、高并发核心改造（面试重点）

### 3.1 多级缓存架构（读热点）
```
用户请求 → Gateway → Caffeine本地缓存(1级) → Redis Cluster(2级) → MySQL
```
- **Caffeine**: 缓存图书详情、分类列表，QPS 10万+，延迟 < 1ms
- **Redis**: 缓存库存、借阅状态，解决热点数据
- **布隆过滤器**: 防止缓存穿透（查询不存在的图书ID）

### 3.2 分布式锁防超借（写热点）
热门图书库存只有 5 本，100 人同时借：
- **Redisson 分布式锁**: `RLock` 保证库存扣减原子性
- **Lua 脚本 + Redis 预扣库存**: 先 Redis 扣减，异步落库，最终一致性
- **乐观锁兜底**: MySQL 版本号防止并发更新

### 3.3 异步化（削峰）
- **RocketMQ**: 借阅成功/逾期提醒/预约释放 全部走消息队列异步处理
- **延迟消息**: 预约图书到期自动释放，用 RocketMQ 延迟队列

### 3.4 限流熔断
- **Sentinel**: 接口限流（QPS 500）、热点参数限流（某本书被疯狂查询）
- **熔断**: book-service 宕机时，Gateway 快速失败，返回兜底数据

## 四、分布式深度

### 4.1 分库分表
- **book 表**: 按 `category_id` 分库，按 `book_id` 分表（ShardingSphere）
- **borrow_order 表**: 按 `user_id` 分库分表，解决单表数据膨胀

### 4.2 分布式事务
跨服务借阅：扣库存（book-service）+ 创建订单（borrow-service）
- **Seata AT 模式**: 保证最终一致性
- **TCC 备用**: 高并发场景下用 TCC 替代 AT，减少锁竞争

### 4.3 分布式链路追踪
- **SkyWalking / Micrometer Tracing**: 一个借阅请求经过 Gateway → User → Book → Borrow，全链路追踪，排查性能瓶颈

## 五、AI Agent 设计（核心差异化亮点）

### 场景：智能借阅助手

**用户说一句话，Agent 自动完成整个借阅流程：**
> "帮我找一本深入讲 JVM GC 的书，要库存充足的，直接帮我借了。"

**Agent 执行链路：**
```
用户输入 → 意图识别 → RAG检索图书知识库 → 查库存(Tool) → 查用户权限(Tool)
→ 调用借阅接口(Tool) → 生成结果返回
```

### 技术实现（Java 生态）

| 技术 | 用途 |
|------|------|
| **Spring AI** / **LangChain4j** | Java 原生 LLM 调用框架，不用写 Python 服务 |
| **PGVector / Milvus** | 向量数据库，存储图书摘要、内容的向量 |
| **RAG** | 用户问"推荐一本适合初学者的并发书"，先检索向量库再生成回答 |
| **Tool Calling** | Agent 可调用的工具：查库存、借书、查用户借阅记录 |
| **ChatMemory** | 多轮对话记忆，"刚才那本再帮我看看有没有" |
| **MCP (Model Context Protocol)** | 如果需要对接外部搜索/图片服务 |

### Agent 服务架构
```
library-agent-service
├── RAG Module: 图书知识库（PDF/文本 → 切片 → Embedding → PGVector）
├── Tool Registry: 注册可调用工具（checkStock / borrowBook / queryUser）
├── ReAct Agent: 推理-行动循环
├── Chat Memory: Redis 持久化对话历史
└── SSE Stream: 流式响应给前端
```

### 智能图书推荐
- 基于用户借阅历史 + 图书内容向量，做**协同过滤 + 向量相似度**混合推荐
- 用 **Spring AI** 做 Embedding，完全 Java 技术栈

## 七、简历写法（已确定）

> **智能图书借阅平台（微服务 + AI Agent）**
> - 将单体架构拆分为 4 个微服务，基于 Spring Cloud Gateway + Nacos 构建服务网格，支撑万级 QPS 查询
> - 设计多级缓存（Caffeine + Redis Cluster）+ 布隆过滤器，图书详情接口 RT 从 120ms 降至 3ms，缓存命中率 98%
> - 针对热门图书限量借阅场景，基于 Redisson 分布式锁 + RocketMQ 异步下单，解决高并发库存超卖问题
> - 基于 ShardingSphere 对 borrow_order 表按 user_id 分库分表（16 库 × 256 表），支撑亿级订单数据
> - 引入 **AI Agent 服务**：基于 Spring AI + LangChain4j 构建智能借阅助手，集成 RAG 知识库与 Tool Calling，支持自然语言完成图书检索→库存查询→自动借阅的完整闭环
> - 全链路接入 SkyWalking 分布式追踪，实现接口 P99 延迟监控与告警
