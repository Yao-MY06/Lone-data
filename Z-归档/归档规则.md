# 归档规则

---
用途：定义何时、如何将不再活跃的内容移出日常视线，保持工作区清洁
更新频率：随归档经验不定期更新
存放位置：`/Z-归档/归档规则.md`
---

## 一、归档的核心哲学

**归档 ≠ 删除**

归档是把不再活跃使用的内容移到"储藏室"。你知道它在哪里，但你的日常视线中不出现。

为什么需要归档？
- 减少视觉噪音（打开文件夹只看到当前重要的东西）
- 降低决策疲劳（不用每次都判断"这个还重不重要"）
- 保留历史记录（未来可能需要回顾）

> 如果你的PARA系统是一个房间，归档就是把过季的衣物收进储物箱。你不会扔掉它们，但你也不想让它们占用衣橱的主要空间。

## 二、何时归档

### 项目归档时机

| 条件 | 时间 | 操作 |
|------|------|------|
| 项目通过验收 | 验收通过后2周 | 移入 `Z-归档/项目/` |
| 项目暂停超过1个月 | 暂停满1个月时 | 移入 `Z-归档/暂停项目/` |
| 项目被取消 | 取消决定时 | 移入 `Z-归档/已取消/` |

**2周缓冲期的意义**：项目"完成"后可能还有bug修复、后续调整、经验总结。2周内没有新的修改，说明真的可以归档了。

### 日记归档时机

| 条件 | 时间 | 操作 |
|------|------|------|
| 晨间日志 | 超过1年时 | 移入 `Z-归档/日记/晨间日志/YYYY年/` |
| 周复盘 | 超过1年时 | 移入 `Z-归档/日记/周复盘/YYYY年/` |
| 月度规划 | 超过1年时 | 移入 `Z-归档/日记/月度规划/YYYY年/` |

### 知识笔记归档时机

| 条件 | 判断标准 | 操作 |
|------|---------|------|
| 知识笔记确认不再活跃引用 | 连续3个月没有任何反向链接引用 | 移入 `Z-归档/知识笔记/` |
| 文献笔记已转化为永久笔记 | 知识清理时确认转化完成 | 移入 `Z-归档/知识笔记/文献笔记/` |
| 教程/课程学习完成后 | 课程通过验收且笔记已整理 | 移入 `Z-归档/学习资料/` |

### 资源归档时机

| 条件 | 时间 | 操作 |
|------|------|------|
| 资源链接失效 | 发现时 | 删除（不是归档，直接删） |
| 资源确认不再需要 | 每学期审计时 | 删除或归档 |

## 三、归档流程检查清单

在将任何内容移入 `Z-归档` 之前，必须完成以下步骤：

- [ ] **1. 确认归档理由**（符合上述"何时归档"的哪一条）
- [ ] **2. 确认内容完整性**（文件夹内没有缺失文件）
- [ ] **3. 确认README或说明文件存在**（让未来的你知道这个文件夹里是什么）
- [ ] **4. 确认GitHub已push**（如果是代码项目）
- [ ] **5. 确认关键知识已提取**（重要笔记已转化为永久笔记或链接到知识库）
- [ ] **6. 填写归档说明**（见下模板）

## 四、归档说明模板

每个归档的文件夹内必须包含一个 `归档说明.md`：

```markdown

## 项目名称/内容描述
（一句话说明这是什么）

## 归档日期
YYYY-MM-DD

- [ ] 已取消

## 关键产出
- （列出最重要的2-3个产出物）

## 学到的关键点
1.

3.
```

## 六、归档不=删除：搜索策略

归档的内容依然可以被找到：

1. **按时间找**：所有归档按年份分组，你知道大概时间就能找到
2. **按类型找**：项目/日记/知识笔记/学习资料，分类清晰
3. **按归档说明找**：每个归档都有说明文件，包含关键词描述
4. **搜索工具**：用系统的文件搜索（Everything/Spotlight）搜索关键词

## 七、定期归档审计

**每学期末（大约是6月底和1月底），花30分钟做一次归档审计：**

- [ ] 检查 `Z-归档/` 中是否有内容超过2年从未被查看过 → 考虑删除
- [ ] 检查 `暂停项目/` 中是否有可以重新启动或彻底取消的 → 做决策
- [ ] 检查归档文件夹结构是否混乱 → 整理
- [ ] 统计本学期完成了多少个项目 → 写入学期总结

## 八、归档的快速决策流程

```
这个东西还需要日常看到吗？
  ├─ 是 → 留在原处
  └─ 否 → 是什么类型？
      ├─ 项目 → 有README？ → 写归档说明 → 移入 Z-归档/项目/YYYY/
      ├─ 日记 → 按年份分组 → 移入 Z-归档/日记/类型/YYYY/
      ├─ 笔记 → 知识已提取？ → 移入 Z-归档/知识笔记/
      └─ 资源 → 还有价值？
          ├─ 是 → 移入 Z-归档/学习资料/
          └─ 否 → 删除
```

> 归档的意义在于"眼不见为净"。你不归档，你的 `02-项目管理` 就会变成20个文件夹的烂摊子，你每次打开都会被视觉噪音轰炸，然后你就放弃使用这个系统了。归档是一种温柔但必要的断舍离。
